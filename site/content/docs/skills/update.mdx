title: /ashlr-update
description: Update the ashlr-plugin to the latest version from its git remote.
---

## When to use

When `/ashlr-doctor` reports a newer release, or before starting a long session.

## What it does

1. Finds the install: `$CLAUDE_PLUGIN_ROOT`, the legacy `~/.claude/plugins/ashlr-plugin/`, or the newest `~/.claude/plugins/cache/<marketplace>/ashlr/<version>/`, whichever is a git checkout first. If none is, it tells you to reinstall from the marketplace and stops.
2. Records the current commit, then runs `git pull --ff-only`.
3. If the pull is blocked by local changes to files that upstream now gitignores (runtime output from the genome hooks), it resets those files and pulls again. Any other conflicting file is listed and left for you to resolve.
4. Runs `bun install` and refreshes `~/.ashlr/last-project.json` so the tools see the current project.
5. Prints the old and new commit and the one-line log between them.

The cache directory keeps the version it was installed with, even after pulls. Claude Code reads the version from the checkout's `plugin.json`, not from the directory name.

## Output

```
ashlr-plugin updated: <old-sha> → <new-sha>
Changes:
  <oneline log, or "already up to date">

⚠ MCP servers run from the old code until you reload.
  Fastest:  run  /reload-plugins
  Full:     quit Claude Code and start a fresh session
```

The reload is required: Claude Code does not hot-reload the long-lived MCP server processes after a pull.

If nothing changed: `ashlr-plugin already up to date at <sha>.`
