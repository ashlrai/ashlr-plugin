## When to use

After install, after upgrading, or whenever you want a quick confirmation that the plugin is active and its MCP server answers.

## What it does

Prints a compact status block:

1. **Plugin version** from `.claude-plugin/plugin.json`
2. **Server** — calls `ashlr__savings`; reachable if it returns
3. **Genome** — whether `.ashlrcode/genome/` exists in the current project, with a pointer to `/ashlr-genome-init` if not
4. **Core library** — the installed `@ashlr/core-efficiency` version, or `core: not installed` with a hint to run `bun install` in the plugin folder
5. **Session savings** from `ashlr__savings`

It always appends a **Telemetry snapshot** from `scripts/telemetry-status.ts`: the LLM provider that would be picked now, embedding-cache hit rate, genome sections and `ashlr__grep` genome fire-rate, the 24h block-to-ashlr conversion rate, and the opt-in telemetry mode. Any field without data shows `—` instead of an error.

`/ashlr-status --context` also appends an **Embedding cache** section from `scripts/context-status.ts`. With `ASHLR_CONTEXT_DB_DISABLE=1` set, that section reads `ashlr context-db: disabled (ASHLR_CONTEXT_DB_DISABLE=1)`.

## Output

Versions, state and counts are illustrative and vary by install and session.

```
ashlr-plugin v1.38.7
  server:  ✓ reachable
  genome:  ✓ (.ashlrcode/genome found)
  core:    @ashlr/core-efficiency@0.3.0
  session: 12 calls, ~8,450 tokens saved

## Telemetry snapshot
  llm-provider:   anthropic (ANTHROPIC_API_KEY set)
  embed-cache:    0 entries · —
  genome:         1 sections · last-50 grep fire-rate —
  block→ashlr:    — (no data yet)
  opt-in telemetry: OFF (default) · to enable: ASHLR_TELEMETRY=on or config.json { "telemetry": "opt-in" }
```
