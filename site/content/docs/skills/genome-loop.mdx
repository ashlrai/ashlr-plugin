## When to use

When you want to see whether the genome loop is on, how many proposals are waiting, force a consolidation, or turn the loop off.

## How the loop works

A PostToolUse hook appends architecture- and decision-flavored observations to `.ashlrcode/genome/proposals.jsonl`. A SessionEnd hook consolidates them back into the genome's section files once 3 or more are pending. This command reports on that loop and switches it on or off.

## Subcommands

| Command | What it does |
|---|---|
| `/ashlr-genome-loop` or `/ashlr-genome-loop status` | Show whether the loop is on, the pending proposal count and the last consolidation time |
| `/ashlr-genome-loop run` | Force a consolidation pass on the current project's genome (`scripts/genome-auto-consolidate.ts`) |
| `/ashlr-genome-loop on` | Set `"genomeAuto": true` in `~/.ashlr/config.json` |
| `/ashlr-genome-loop off` | Set `"genomeAuto": false` in `~/.ashlr/config.json` |

`ASHLR_GENOME_AUTO=0` in the environment also turns the loop off for that shell.

## Output

`status`, in a freshly initialized genome:

```
ashlr genome loop — on
  pending proposals: 0 (/work/demo-app/.ashlrcode/genome/proposals.jsonl)
  last consolidation: (never)
```

When the loop is off, the first line says why: `off (env ASHLR_GENOME_AUTO=0)` or `off (~/.ashlr/config.json)`. The last consolidation time is the first field of the last line of `~/.ashlr/genome-consolidation.log`.

`on` and `off` print `ashlr genome loop: enabled` or `ashlr genome loop: disabled`. `run` prints nothing when fewer than 3 proposals are pending; the command then reports "No pending proposals to consolidate (need ≥ 3)."
