## When to use

When something isn't working: tools not appearing, status line missing, savings not accumulating, or a tool call returning an unexpected error.

## What it does

Runs `bun run scripts/doctor.ts` from the plugin root and prints its output verbatim, so you can paste it into a GitHub issue. If the last line reports any warnings or failures, the agent offers to apply the fixes. Each `⚠` or `✗` line carries the exact command to run, and nothing is applied without your yes.

The report has these sections:

- **install** — plugin root, Bun, `node_modules` dependencies, and the `phantom` CLI
- **companions** — the other Ashlr tools on this machine: phantom (`phm`), phantom-secrets (`phantom`), locus, lexicon, ashlr-md (`mdopener-mcp`) and ashlr-stack (`stack`). Each gets `--ashlr-handshake --json` with a 2 second timeout and a minimal environment, so no token reaches it. These lines are informational and never count as warnings or failures.
- **mcp servers** — each server and the tools it lists
- **runtime state** — `~/.ashlr/stats.json`, genome and manifest freshness, the `attribution` and `editBatchingNudge` settings, the tool allowlist, the status line, Pro sign-in, the ONNX model and the project hint
- **cloud** — `GET /healthz` on the backend with a 3 second timeout. An unreachable backend is a warning only. `ASHLR_API_URL` overrides the URL, and `ASHLR_API_URL_DISABLE=1` skips the check.
- **summarizer routing**, **hooks** and **hook performance** (p50/p95 per hook)

`bun run scripts/doctor.ts --json` prints the whole report as JSON. `/ashlr-doctor --errors` also appends a **Recent errors** section from `scripts/errors-report.ts`.
