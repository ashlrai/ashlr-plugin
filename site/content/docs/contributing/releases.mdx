title: Releases
description: How a version bump on main becomes a tag, a full CI run, a GitHub release and an npm publish.
---

Releases are automated. A contributor or agent lands a version bump on `main`. GitHub Actions does the rest: tag, full CI on that tag, GitHub release, npm publish and MCP Registry entry. Nobody publishes from a laptop.

## Version scheme

ashlr uses [semantic versioning](https://semver.org/). Given the plugin's role as a tool layer, the rules are:

- **Patch** (`1.x.Y`): bug fixes, documentation, no API changes
- **Minor** (`1.Y.0`): new tools, new skills, backward-compatible schema changes
- **Major** (`Y.0.0`): breaking changes to tool input schemas or the stats schema

`package.json` is the source of truth. The Claude Code and Codex plugin manifests and the marketplace manifest must match it. `bun run version:check` enforces this on every PR.

## Cut a release

1. Move the `## [Unreleased]` notes in `CHANGELOG.md` into a dated section, `## [X.Y.Z] - YYYY-MM-DD`.
2. Bump every manifest at once:

   ```sh
   bun run version:bump X.Y.Z
   ```

   This writes `package.json`, `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json` and `.claude-plugin/marketplace.json`. It does not touch git, tags or the changelog.
3. Refresh the derived release facts:

   ```sh
   bun run fresh:sync                 # README badge and install pin, FAQ, CHANGELOG summary, docs/README.md
   bun run site/scripts/gen-docs.ts   # site facts, including the Latest release page
   ```

   Commit the refreshed files, but not `site/lib/docs.generated.json` (see [AGENTS.md](https://github.com/ashlrai/ashlr-plugin/blob/main/AGENTS.md)). The `fast checks` CI job fails a bump that forgot these site facts.
4. Open a PR and merge it.

## What runs after the merge

| Workflow | Trigger | What it does |
|---|---|---|
| `auto-tag.yml` | `package.json` changes on `main`, `ci` completes on `main`, or manual dispatch from `main` | Creates `vX.Y.Z` for the manifest version if that tag is missing and every required check on the commit is green. Then it starts `release.yml`. |
| `release.yml` | a `v*.*.*` tag, or manual dispatch for an existing tag | Reuses or starts a full `ci.yml` run on the exact tag and requires it to pass on Linux, macOS and Windows. Checks that the manifests match the tag, runs typecheck and tests, and creates the GitHub release with the changelog notes, the VS Code `.vsix` and a static site zip. Then it publishes to npm with provenance through trusted publishing (OIDC, no npm token). |
| `mcp-registry.yml` | a GitHub release is published | Publishes `server.json` to the official MCP Registry. |
| `deploy-site.yml` | `site/**` changes on `main` or in a pull request, or manual dispatch | Builds the site. On `main` or a dispatch it deploys [plugin.ashlr.ai](https://plugin.ashlr.ai); on a pull request it deploys a preview. Both deploys need the repository's Vercel secrets, so without them (as on a fork PR) it is a build-only check. It is not part of `CI Gate`. |
| `deploy-server.yml` | `server/**` changes on `main` | Tests and deploys the optional Pro backend. |

The release gate is described in [docs/release-qualification.md](https://github.com/ashlrai/ashlr-plugin/blob/main/docs/release-qualification.md). A failed, cancelled or incomplete full run cannot publish. Only a manual `ci.yml` run with the `full` scope (run name `ci/full`) on the exact tag counts; a daily run or a `windows-diagnostics` run does not.

## Re-run a release

If a merged version bump has no tag yet, for example because a required check was still pending after `auto-tag.yml`'s bounded wait (about ten minutes), start it again from `main`. It applies the same gate: it tags only when the tag is missing and every required check on the `main` head is green.

```sh
gh workflow run auto-tag.yml --repo ashlrai/ashlr-plugin --ref main
```

To build an existing, qualified tag again, dispatch the sanctioned workflow from `main`:

```sh
gh workflow run release.yml --repo ashlrai/ashlr-plugin --ref main -f version=X.Y.Z
```

The npm step skips a version that is already on the registry. Do not move a tag that is already in use. If a candidate fails, fix forward on `main` and release a new, unused version.

Check what is live with:

```sh
npm view ashlr-plugin version dist-tags --json
```

## Changelog format

`CHANGELOG.md` follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/):

```markdown
## [X.Y.Z] - 2026-01-15

### Added
- ashlr__diff_semantic: AST-aware diff summarization

### Fixed
- ashlr__read: incorrect line count on Windows CRLF files

### Changed
- Stats schema bumped to v2 (auto-migrated on first run)
```

## Deprecation policy

Tool input schema fields are deprecated for one minor version before removal. Deprecated fields are listed in the changelog.
