The default router exposes **54 MCP tools**. Flag-gated tools are listed separately below with their activation condition. Descriptions come from the same catalog used by MCP tools/list.

### ashlr__glob

Token-efficient glob pattern matching. Returns compressed output instead of raw file lists: ≤20 matches listed verbatim; &gt;20 matches grouped by top-level directory with counts and sample paths. Honors .gitignore automatically inside git repos (uses `git ls-files`), otherwise walks the filesystem while skipping node_modules, dist, build, .git, .next, .cache, .turbo, __pycache__, .venv. Replaces the native Glob tool ; produces 70-90% fewer tokens on large repos.

### ashlr__tree

Token-efficient project structure view. One call returns a Unicode box-drawing tree with per-directory size/file-count and optional per-file LOC. Honors .gitignore automatically inside git repos, otherwise skips a standard exclusion set (node_modules, dist, build, .git, .next, .cache, .turbo, __pycache__, .venv). Replaces the 3-5 orientation calls (ls -la + find + multiple Reads) Claude Code normally makes when opening a repo.

### ashlr__ls

Gitignore-aware directory listing. Compact columnar output with elision past maxEntries (default 80). Set bypassSummary:true to see all entries.

### ashlr__diff

Fast adaptive git diff. Use instead of native Bash 'git diff | cat' when reviewing changes ; avoids dumping thousands of lines into context. Compresses by auto-selecting stat-only (&gt;500 changed lines), stat+hottest-hunks (100–500), or full patch (&lt;100); typical savings 60–95% on large diffs. Accepts any git ref plus pseudo-refs 'staged', 'unstaged', 'working'. For refactor/rename reviews use ashlr__diff_semantic instead.

### ashlr__webfetch

Token-efficient URL fetcher. Aggressively extracts article text from HTML (title + main content, strips nav/scripts/styles), pretty-prints + array-elides JSON, byte-caps plain text. Default cap 100 KB vs native WebFetch which is uncapped. Use instead of WebFetch when you want article content ; saves 60-95% tokens on typical pages.

### ashlr__read

Read a file with snipCompact truncation (head + tail, elided middle). Use instead of native Read when the file is &gt;2KB ; avoids returning the full payload; compresses by preserving only the structurally significant head and tail; typical savings 60–90% on large files. Pass bypassSummary:true to get the full file when you need it.

### ashlr__flush

Flush all queued ashlr__edit writes to disk immediately and return a summary of what was committed. Use when you need to read a file you just edited, or at the end of a multi-edit sequence.

### ashlr__edit_structural

Rename a symbol with AST awareness (one file or N files). Use instead of native Edit when renaming variables/functions/types ; avoids accidental matches in strings/comments. Compresses by returning only a rename summary; typical savings 80–95%. operation='rename': file-local. operation='rename-cross-file': across rootDir. operation='extract-function': extract byte-range to new function. Supports .ts/.tsx/.js/.jsx. dryRun=true previews. Use ashlr__edit for literal edits.

### ashlr__rename_file

Rename (move) a source file AND update every import specifier in the project that resolved to it. Handles extension elision ('./foo' → './bar'), directory-index resolution ('./foo' when foo/index.ts), and skips bare package specifiers. Refuses if 'to' already exists, 'to's parent directory is missing, paths escape cwd, or either path is a binary file. Supports dryRun. Complements ashlr__edit_structural (which renames identifiers, not module paths).

### ashlr__search_replace_regex

Regex-based bulk substitution across files in one call. Use instead of native Edit when patterns are mechanical (X→Y across many call sites) ; native Edit doesn't support regex. Compresses by returning a per-file match-count summary; typical savings 80–95%. Global flag is implicit; supports i/m/s/u; capture groups ($1, $2, $&) in replacement. Use dryRun=true to preview. For literal single-file edits use ashlr__edit. For AST-aware renames use ashlr__edit_structural.

### ashlr__websearch

Token-efficient web search wrapper. Deduplicates results by domain, truncates snippets to ~500 chars, and synthesizes a 1-paragraph summary when more than 3 results are returned. Use instead of WebSearch to save 40-80% tokens on search result payloads. Args: query (required), maxResults (default 5), summarize (default true).

### ashlr__task_list

Token-efficient task list viewer. Filters by status/owner, limits to max rows (default 30), and returns a compact column view: taskId, status, subject (80 chars), ageMin. Use instead of TaskList to avoid verbose task payloads. Args: status (optional filter), owner (optional filter), limit (default 30).

### ashlr__task_get

Token-efficient single task viewer. Fetches a task by ID and snipCompacts the description if it exceeds 2KB (head + tail with elision marker). Returns: taskId, status, subject, descriptionCompact, fullLength. Use instead of TaskGet for long-description tasks. Args: taskId (required).

### ashlr__notebook_edit

Edit a single cell in a Jupyter notebook (.ipynb). Use instead of native NotebookEdit when the notebook is &gt;5KB or has many unrelated cells ; only the edited cell and its immediate neighbors are returned, with `[N cells unchanged]` for the rest. The full notebook is never echoed. Typical savings: 65-75% on multi-cell notebooks. Args: notebookPath, cellIndex, newSource, cellType (optional: code|markdown).

### ashlr__pipe

[EXPERIMENTAL] Executes model-authored JS code server-side ; off by default, enable with ASHLR_PIPE_ENABLE=1. Run a JS expression that calls ctx.&#123;grep,read,ls,glob&#125; internally ; intermediate results NEVER enter context, only the return value does. Typical 80–95% token savings vs calling tools individually. ctx methods accept the same args as the ashlr__ tools they wrap. ctx.bash requires the additional ASHLR_PIPE_ALLOW_BASH=1 flag. Example: `return await ctx.grep({pattern:'TODO',cwd:'my project'});` returns the grep tool's text output as a string, which may include status messages.

Requires `ASHLR_PIPE_ENABLE=1` (experimental, excluded from the default count).

### ashlr__fleet_state

Read fleet lane targets and holds, the last 20 job states and latest leader event from ~/.ashlr/fleet/&#123;targets.json,holds.json,jobs.jsonl,leader-events.jsonl&#125;; when every fleet file is absent, the equivalent state comes from ~/.ashlr-runs/&#123;queue/slots.json,HOLD,metrics/jobs.jsonl,queue/dispatch-events.log&#125; plus a queue/run/ split of jobs into live, ghost and held (phdrip markers). Read-only; missing or invalid files are reported as unavailable. Never opens environment or secret files.

### ashlr__fleet_events

Read typed events from ~/.ashlr/dispatch-events.log and ~/.ashlr/metrics/jobs.jsonl. JSON records or timestamped dispatch text; complete lines only, dispatch source first. Opaque per-source cursor supports polling; limit defaults to 200 (maximum 200). Missing, unsafe and malformed files are reported without raw contents. Read-only.

### ashlr__fleet_intent

Append an audited pending request to ~/.ashlr/fleet/intents.jsonl; never execute it. pause/resume require lane; kill requires job_id; reassign requires job_id and lane; set-slot requires lane and slots (0–1024). All requests require requested_by (caller-supplied attribution) and reason. No other fields or paths accepted.

### ashlr__fleet_session

Read a fleet job's latest metadata and metrics, its live children (jobs whose parent_job_id names it), PR URL, worktree and last 150 log lines from ~/.ashlr/fleet/jobs.jsonl (or ~/.ashlr-runs/metrics/jobs.jsonl when the fleet log is absent) and logs/&lt;job_id&gt;.log. Token-like strings are redacted; missing or unsafe files are reported. Read-only; accepts a job ID, never a path.

### ashlr__fleet_act

Request fleet pause/resume (lane), kill (job_id), reassign (job_id, lane), slots (lane, slots 0–1024), or steer (job_id, message). Requires requested_by (caller attribution) and reason. dry_run defaults true: audit preview only. false appends a pending controller request, never claims execution. A kill cascades: one extra kill request per live child of the target (parent_job_id links) is appended naming the parent request. All valid calls append to ~/.ashlr/fleet/actions.jsonl; controller execution is external. No caller-selected paths.

### ashlr__fleet_snapshot

Read the ~/.ashlr/fleet snapshot as structured JSON: lanes (targets and holds), complete job upserts beyond the 20-row UI tail, job-reported PR links, the latest leader event and per-source errors. When the fleet files are absent the equivalent state comes from ~/.ashlr-runs. Pass the opaque cursor from a previous response to get only net changes and removed ids. Missing or unsafe sources are null with error entries. Read-only; accepts an optional cursor, never paths.

### ashlr__fleet_direction

Read the project direction (VISION.md by default, or another top-level *.md filename via direction) and append governed proposals to DIRECTION-PROPOSED.md in the project root. propose requires author and text (at most 8192 characters); proposals are suggestions, never adopted direction. MASON-INBOX.md and VISION.md stay protected: DIRECTION-PROPOSED.md is the only writable file, under nofollow and single-link checks. No caller-selected paths.

### ashlr__fleet_lanes

Read fleet lane targets, holds, job counts and source errors as JSON using fleet-steer lanes. Read-only; fixed ~/.ashlr/fleet root, no arguments or paths.

### ashlr__fleet_proposals

Read the fleet steering proposal journal and skipped-record count as JSON using fleet-steer proposals. Read-only; fixed ~/.ashlr/fleet/steer-proposals.jsonl, no arguments or paths.

### ashlr__fleet_propose

Propose fleet reassign (job_id, lane) or set-slots (lane, slots 0–1024) using fleet-steer. Requires author (caller attribution) and reason. Returns JSON; refuses duplicate pending proposals. Only appends ~/.ashlr/fleet/steer-proposals.jsonl for controller review; never applies changes. No caller-selected paths.

### ashlr__fleet_browser

Read a fleet job's browser frames from ~/.ashlr/fleet/browser/&lt;job&gt;: paged frame paths, the latest frame, current URL and an opaque cursor for polling. job is a job id (validated like the /api/browser route), never a path; limit defaults to 100 (maximum 200). Read-only.

### ashlr__fleet_resources

Read the shared fleet resource ledger at ~/.ashlr-runs/resources.json: per-lane availability, cap headroom, slot targets versus running jobs, jobs and tokens per hour and projected exhaustion, plus per-source status. Regenerates the ledger via `ashlr resources --json` when resources.json is missing or over 60 seconds old; fresher ledgers serve from disk without re-running. Read-only; accepts no arguments or paths.

### ashlr__grep

Search for a pattern. Use instead of native Grep always ; genome-aware when .ashlrcode/genome/ exists (returns only the most relevant pre-summarized sections + merged PRs + closed issues), falls back to ripgrep with LLM summarization for large result sets. Compresses by filtering to relevant chunks; typical savings 70–90%.

### ashlr__edit

Single literal search/replace in one file, returns only a diff summary. Use instead of native Edit when the file is &gt;5KB or the combined before/after is &gt;=80 chars ; avoids the full file round-trip. Compresses by returning only the changed lines; typical savings 80%. In strict mode (default) requires exactly one match. For many edits across files use ashlr__multi_edit instead. For symbol renames use ashlr__edit_structural instead.

### ashlr__write

Write content to a file without echoing the full content back. If the file already exists, delegates to ashlr__edit (full-file replace, compact diff response). If the file is new, creates it and returns a compact acknowledgment (path, bytes, sha8). Either way, the full file content is never returned ; ~80% token savings vs native Write.

### ashlr__http

HTTP fetch with compressed output. Readable-extracts main content from HTML, pretty-prints + array-elides JSON, bounded byte cap. Refuses non-http/https schemes and private hosts by default.

### ashlr__logs

Tail a log file efficiently. Reads the last N lines (default 200), detects severity from bracketed tags, bare prefixes, JSON/logfmt level fields, and Python tracebacks, filters by level and/or ISO timestamp, and collapses runs of identical consecutive lines into '(42x) ...'. Supports glob paths. Lines with no parseable timestamp are skipped (never fatal) when 'since' is set.

### ashlr__sql

Run SQL against SQLite or Postgres and get a compact, token-dense text result. Replaces the typical 3-4 Bash calls (psql / sqlite3 + parse stdout) with one tool call. Supports SELECT, DDL, DML, EXPLAIN, and a schema-introspection mode.

### ashlr__diff_semantic

AST-aware (heuristic) git diff summarization. A 200-line rename-refactor across 20 files renders as one line. Detects: symbol renames across &gt;= 3 files, signature-only changes, formatting-only diffs. Degrades gracefully to compact diff output when no semantic patterns are found. Use instead of ashlr__diff when reviewing refactors, renames, or large reformatting commits.

### ashlr__pr

Fetch a GitHub PR and return a compact review-ready summary (header, reviews, unresolved comments, status checks). Read-only ; never approves, comments, or merges. Saves 60-90% of the tokens a raw `gh pr view` dump would cost.

### ashlr__issue

Fetch a GitHub issue and return a compact header + body + comment list. In 'thread' mode, each comment is rendered with snipCompact on &gt; 500 char bodies. Read-only.

### ashlr__pr_comment

Post a comment on a GitHub PR. Pass pr:"current" to target the PR for the checked-out branch. Returns the new comment URL.

### ashlr__pr_approve

Approve a GitHub PR with an optional review body. Refuses to approve your own PR. Pass pr:"current" to target the PR for the checked-out branch.

### ashlr__issue_create

Create a new GitHub issue with title + body and optional labels/assignees. Returns the new issue number and URL.

### ashlr__issue_close

Close a GitHub issue with an optional closing comment and reason (completed|not_planned).

### ashlr__genome_propose

Queue a proposed update to a named genome section. Fire-and-forget: the proposal is appended to the pending queue and will be merged into the genome on the next ashlr__genome_consolidate call. Use this to record project decisions, new strategies, architectural discoveries, or lessons learned so they persist across sessions.

### ashlr__genome_consolidate

Merge pending proposals into the genome. Without `model` (and without $ASHLR_LLM_URL) runs a deterministic sequential-apply; with an LLM configured by $ASHLR_LLM_URL it merges conflicting proposals for the same section.

### ashlr__genome_status

Show pending proposals and recent mutations for the current genome. Compact report suitable for inline context.

### ashlr__fleet_ghosts

Read ghost slots, stalled jobs and reported versus live job counts by lane from ~/.ashlr/fleet/runs. Read-only JSON; unknown process liveness remains explicit. Accepts no arguments or paths; missing sources return an error.

### ashlr__fleet_dirty_triage

Read the DIRTY PR backlog, ranked as recut-worthy, superseded or stale with C1-C6 reasons and counts. Optional repos (up to 20 owner/name values) defaults to the current repository; staleDays defaults to 14. Read-only GitHub queries through a pinned Locus identity; never changes PRs or branches. Returns JSON including partial errors and truncation.

### ashlr__multi_edit

Many edits across multiple files in one atomic call. Use instead of N separate Edit or ashlr__edit calls when touching more than one file ; N round-trips collapse to 1, with full rollback on any failure. Compresses by returning one consolidated diff summary; typical savings (N−1) × per-call overhead. For a single file use ashlr__edit instead. For symbol renames use ashlr__edit_structural instead.

### ashlr__orient

Meta-orientation tool. Answers 'how does X work here?' in a single call: runs a project tree scan, derives keywords from your query, discovers relevant files (genome retriever if .ashlrcode/genome/ exists, else ripgrep), snipCompacts them, and asks a local LLM for a ≤600-char synthesis plus a suggested next tool call. Replaces 3-5 round-trips (tree + grep + multiple reads). Read-only.

### ashlr__bash

Run a shell command. Use instead of native Bash when the command produces verbose output (git log, test runners, npm install, find, ps). Auto-compresses stdout &gt; 2KB and emits compact structured summaries for common commands (git status, ls, find, npm ls). stderr is never compressed. Refuses catastrophic patterns; use ashlr__read for cat. Typical savings 60–90% on verbose commands.

### ashlr__bash_start

Spawn a long-running shell command in the background and return a session id. Use ashlr__bash_tail to poll incremental output, ashlr__bash_stop to kill, ashlr__bash_list to enumerate. Ideal for watchers, tails, long builds, and anything where streaming &gt;&gt; one-shot.

### ashlr__bash_tail

Read new stdout/stderr since the last poll for a background session. Auto-compresses the tail window when &gt; 2KB. If wait_ms &gt; 0, blocks (event-driven) until output arrives or the process exits, up to that ceiling.

### ashlr__bash_stop

Kill a background session by id. Sends SIGTERM (configurable) and escalates to SIGKILL after 2s if still alive.

### ashlr__bash_list

List active background sessions: id | pid | started | cumulative bytes | command.

### ashlr__test

Run a test suite and return structured, token-efficient failure output. Supports bun test, vitest, jest, pytest, go test, and a generic fallback. Parses runner output into pass/fail/skip counts plus per-failure file:line + message + stack ; eliminating the read-source-fix-rerun loop that wastes 25–30% of tokens on test-driven workflows.

### ashlr__savings

Show estimated tokens and cost saved by ashlr tools in the current session and lifetime totals. Use instead of manually counting tool calls to measure ashlr efficiency.

### ashlr__ask

Single-tool entry point for ashlr. Accepts a natural-language question and auto-routes to the correct underlying tool (ashlr__read, ashlr__grep, ashlr__orient, ashlr__tree, or ashlr__glob) using deterministic rules ; no LLM in the routing step. Output always starts with a one-line trace showing which tool fired and why.
