# Status line fields

The Claude Code status line is produced by `scripts/savings-status-line.ts`. Once installed, Claude Code refreshes it during the session. For example, with the sparkline and tips disabled, an established session with no savings might show:

```text
ashlr · ctx: 50% · session +0 ≈$0.00 · lifetime +1.5K (est.)
```

The fields below show additional examples individually: optional fields depend on data, settings, terminal capabilities, and available width. A `·` separates segments. `+` indicates tokens saved, not tokens spent. Counts below 1,000 are whole tokens; `K` means thousands and `M` millions, rounded to one decimal.

| Field | Meaning and units | When absent or unknown |
| --- | --- | --- |
| `ashlr` | Identifies the status line. | The master `statusLine` setting can disable the entire line; an error can also produce an empty line. |
| `· 7d ⠀⡀⡄⡆⡇⣧█` | The heartbeat changes during the 4.5 seconds after a session save when animation is enabled; otherwise it is an idle dot. The seven sparkline cells show daily tokens saved, oldest to newest, for today and the previous six UTC days, scaled relative to the largest day; `7d` appears when the width budget exceeds 100 columns. | Missing daily values are treated as zero. Both are hidden by `statusLineSparkline: false`; animation and glyphs depend on terminal capabilities. |
| `ctx: 50%` | Context used as a percentage of the supplied context limit, rounded to a whole percent and capped at 100%. When truecolor is supported, the unrounded percentage is green below 60%, yellow from 60%, orange from 80%, and red and bold from 95%. | Hidden unless stdin supplies numeric `context_used_tokens` and a positive `context_limit_tokens`; a token count alone is insufficient. It can also be dropped for width. |
| `session ↑+12.3K` | Tokens saved for the current session, summed over matching session buckets. The candidates include the explicit session ID, a recent session hint, and a process-derived fallback; they can cover multiple buckets for one session. `↑` (or ASCII `+`) indicates a save within the last four seconds (inclusive); ASCII displays `++` because the activity marker precedes the savings `+`. | No matching bucket defaults to zero; legacy stats may use a shared session counter. With no stats file, the line says `(waiting for first tool call)`; with fewer than five lifetime calls and zero session savings it says `session +0 (collecting…)`. Corrupt stats fall back to zero. `statusLineSession: false` hides the segment. |
| `≈$0.01` | Approximate US dollars saved for the session: saved tokens multiplied by an input-token price. The detected summarizer price is used unless `ASHLR_PRICING_MODEL` overrides it; a zero-priced detected summarizer falls back to main-model pricing when no override is set. Values under one cent display as `≈$0.00`. This is an estimate, not a bill. | A zero or unusable token count displays `≈$0.00`; the cost can be dropped for width. |
| `lifetime +1.2M (est.)` | Tokens saved in local lifetime stats. `(est.)` displays the total across calls; once at least ten calls have measurements, `(API-measured)` displays only the measured-call total, which can be lower because it excludes unmeasured calls. | Normally hidden if the file is missing or the selected total is zero, or when `statusLineLifetime` is false. Width reduction can rebuild the segment without its method label and can show zero. |
| `* 3d streak` | Stored current streak of active days from `~/.ashlr/streaks.json`; it is not recalculated when the status line reads it. | Hidden below three days or when streak data is missing or unreadable; it can be dropped for width. |
| `☁ 2 machines` | Number of machines in the cached cross-machine aggregate for a Pro user. | Hidden without a usable Pro token or aggregate, or when the count is at most one; it can also be dropped for width. The displayed cache may be stale: the pull uses a one-hour freshness window, but the status-line reader does not reject an expired cache. |
| `brief: concise` | Active user-level brief configuration, read from `~/.ashlr/brief.json`. | Hidden if the file is missing or unreadable, the level is missing, or it is `off`; it can also be dropped for width. |
| `last: ashlr__read +5.0K [2s ago]` | Recent save age in whole seconds (minimum `1s ago`) and a tool's session token savings. The tool is the entry with the largest accumulated savings in any matching session bucket, a proxy for the most recent tool; the number is that entry’s accumulated savings, not necessarily the last call’s saving or a sum across buckets. | Shown through 60 seconds inclusive after the session's last saving timestamp and when a tool has positive savings. Missing timestamps or per-tool data hide it; it can be dropped for width. |
| `tip: use /ashlr-savings to see totals` or `↑: 50k+ saved — try Pro (7d trial /ashlr-upgrade)` | A usage tip that rotates daily, or an upgrade hint for an apparently free user with at least 50,000 session tokens saved. | Hidden by `statusLineTips: false` or if it does not fit. `statusLineUpgradeNudge: false` disables the upgrade hint. |

Settings are under `ashlr` in `~/.claude/settings.json`; the master, session, lifetime, tips, sparkline and upgrade-nudge switches default to enabled. The line uses `COLUMNS` (default 80, maximum 120) as its visible-width budget. If a tip does not fit, it is omitted. If the remaining line is too wide, the renderer rebuilds it without the streak, machine count, brief, last-save and lifetime method label, then removes the cost and context in that order, and finally truncates with an ellipsis, potentially cutting a field mid-text. Rebuilding can replace the waiting or collecting message with zero counters and can show a zero lifetime total. Therefore an omitted field is not evidence of a zero value.

Local stats and settings are read from disk with a process-local 300 ms cache that invalidates on file modification. Updates can lag the write; the display has no general stale-data indicator. The last-save age is based on the stored timestamp, and disappears after its window rather than marking old data stale. The cloud machine count can remain visible from an expired cache. A blank line, zero fallback, or absent field should not be interpreted as proof that the underlying data is current.

## Installation and troubleshooting

Ask `/ashlr-settings` to install the status line, or run the installer command in the [README](https://github.com/ashlrai/ashlr-plugin#status-line). The installer adds a command to Claude Code's `~/.claude/settings.json` without replacing an existing custom status line. If the line is missing, check that command and the `ashlr.statusLine` setting, or run `/ashlr-doctor`.

See `/ashlr-savings` for detailed totals.
